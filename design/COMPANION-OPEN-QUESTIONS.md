# Companion: принятые решения, открытые вопросы и будущие переработки

Рабочий документ этапа реализации ТЗ `.agents/req/mythras-companion_req_15.11.26.md`.
Обновляется по мере выполнения задач; сюда выносятся решения и вопросы, чтобы не
держать их в переписке. Не является требованием и не публикуется (`docs/` не трогаем).

## 1. Принятые решения

| № | Вопрос | Решение |
|---|--------|---------|
| 1 | Цели модификаторов эффектов для магии | Один `kind: 'magic'` с ключами `theism.poolMax`, `theism.intensity`, `animism.maxSpiritPOW`, `mysticism.totalIntensity`, `sorcery.shapingPoints`. В UI: «дисциплина → показатель». |
| 2 | Дефект R2 (модификатор по имени задевает все одноимённые навыки) | Необязательное `Skill.id`. Идентификатор присваивается при загрузке только навыкам с конфликтующим именем. Модификатор без `skillId` сохраняет прежнее поведение «все одноимённые». |
| 3 | Несколько типов повреждений на локацию | `companion.injuries` хранит `string[]`; старая строка читается как массив из одного элемента. Миграция в `hydrateCharacter`, идемпотентная. |
| 4 | Старые сохранения с ручным `devotionPool` | Сохранённое число считается ручным оверрайдом: показывается «максимум: N (вручную)», кнопка «по рангу» сбрасывает в `ceil(POW / …)` по §8.2. |
| 5 | Ранг анимизма `Spirit Lord` | Лимит связанных духов как у High Shaman (`CHA`). Ранг из списков не удаляется. |
| 6 | Folk Magic и «профильные профессии» | Профессиональность не отслеживаем и `ceil(FM/10)` не считаем: в проекте нет признака профессии, связанной с Folk Magic, а стартовый набор заклинаний сейчас не проверяется. Отображается фактическое количество заклинаний и справочный текст правил. См. §3.3. |
| 7 | Mysticism | Показывается только доступный максимум суммарной Intensity `ceil(Meditation / 10)` и максимум одного таланта `ceil(Mysticism / 20)`. Учёт активных талантов не делается. |
| 8 | Дефекты | R1 (урон при HP выше максимума), R2, R3 (пустой override штрафа брони), R6 (предпросмотр прокачки) — в работе. R5 (усталость как контекст проверки навыка) вне рамок, пока ТЗ этого не требует. |
| 9 | Несколько культов на дисциплину | Сейчас не реализуется. Лист персонажа готовится к массиву записей; модель `Character` и конструктор не меняются. См. §3.1–3.2. |
| 10 | Кубики | Поддерживаем оба режима: виртуальные кубики и ручной ввод физического броска. Анимация — переключателем. |
| 11 | История изменений | Только в сеансе; в JSON персонажа не сохраняется. |
| 12 | Ручной режим прокачки | Называется **«Становление»** и объединяет текущую прокачку с редактированием листа: изучение навыка в листе, прошлое значение → прибавка → итог до сохранения. |
| 13 | Развитие по правилам | Отдельный режим **«Опыт»** (ER, Experience Rolls, тренировки, магия) рядом со «Становлением». |
| 14 | Формат и код друга | Общий формат сохранений не обязателен; код форка использовать можно (лицензию и атрибуцию оформить отдельно). |
| 15 | Травмы | `Отсечена` — только конечности и культя; `Увечье` заменяет «раздробленность», даёт −1 к максимуму HP локации и помятые края; `Пронзена` — стрела в части. Любые доступные для локации травмы сочетаются и снимаются по одной. Легаси `Раздроблена` мигрирует в `Увечье`. |
| 16 | Травма и эффект | Травма автоматически создаёт связанный эффект с автоназванием и окном описания; снятие эффекта снимает травму, снятие травмы снимает эффект. |
| 17 | Эффекты | Добавление и правка — во всплывающем окне; модификаторы в списке показываются как «Характеристика: STR +1». Новый вид модификатора `locationHp` — «Максимальное здоровье локации»; эффект `Увечье` получает его автоматически со значением −1. |
| 18 | Снаряжение и магия в листе | Оружие, броня и предметы добавляются из листа с поиском; у оружия есть фильтр «только мои боевые стили». Заклинания добавляются из листа для Folk Magic, Sorcery и Theism. |

## 3. Будущие переработки структуры персонажа и конструктора

Эти пункты требуют изменения `Character` (и частично билдера). Лист уже строится так,
чтобы добавление записей было изменением данных, а не переделкой интерфейса.

### 3.1. Несколько теистических культов

- Сейчас: один `character.theistCult`, один пул `devotionPool` / `devotionPoolCurrent`.
- Нужно: запись членства на культ с собственными `Devotion`, `Exhort`, рангом и Devotion Pool;
  сумма пулов ограничена POW персонажа (§8.1).
- Требует: массив записей в `Character`, миграция старых сохранений, шаг культа в конструкторе,
  обновление PDF (`character-pdf.component.html`) и `customization`.

### 3.2. Несколько учений в остальных дисциплинах

- Animism: несколько культов с отдельными `Trance`/`Binding` и рангами.
- Sorcery: несколько орденов с отдельными `Invocation` и `Shaping`.
- Mysticism: несколько путей, у каждого свой `Mysticism` (сейчас один `mysticalOrder` и один
  `magic.path`), плюс, при необходимости, интенсивность и признак «тренируется» у талантов
  для учёта активной суммы.
- Folk Magic остаётся общим навыком, отдельных учений не имеет.

### 3.3. Профессиональность Folk Magic

- Нужен признак «профессия специально связана с Folk Magic» (сейчас `career` — свободная строка,
  в `cults.service.ts` и `magic.service.ts` такого соответствия нет).
- Когда конструктор начнёт проверять стартовый набор заклинаний, для таких профессий
  количество заклинаний считается как `ceil(Folk Magic / 10)` вместо `ceil(Folk Magic / 20)`
  (Mythras Core Rules, Folk Magic, стр. 121; ТЗ §9.1).
- До этого момента правило только показывается как справка и не влияет на данные.

## 4. Направление оформления листа

> 16.11.2026 выбрано и применено направление **A. Краснофигурная керамика**
> из `design/concepts/antiquity-sheet.html`: тёмный лак, терракота, бронза.
> Палитра перенесена в `src/ui/_tokens.scss`, Material переведён на тёмную тему,
> плита и травмы перерисованы. Раздел ниже описывает предыдущую итерацию
> (известняк/бронза/олива) и сохраняется как история.

Правка листа выполнена по навыку unslop (`.agents/skills/unslop/SKILL.md`).

- **Продукт.** Игровой лист для настольной Mythras: за столом нужны числа и здоровье, а не украшения.
- **Характер.** Плотный, точный, слегка античный.
- **Мир.** Известняковая плита, бронза, олива — как анатомическая табличка в кабинете лекаря.
- **Моменты.** Одна плита с фигурой, у которой травма меняет саму часть тела; цифры вокруг неё тихие.
- **Подпись.** Культя с линией разреза, штриховка дробления и сквозная линия пронзения вместо значков рядом с моделью.

Что изменено по проходам: сетка карточки — две колонки (плита слева, числа одной колонкой справа), поэтому зоны больше не растягиваются до высоты самой высокой; характеристики — компактный ряд 7 плиток в одной строке с Frame/ростом/весом; атрибуты, AP, MP, Luck и Healing Rate — восемь плиток в 4 колонки; список локаций стоит рядом с моделью, строки 26 px; модель перерисована (шея, плечи, руки вне силуэта торса, ступни), подписи внутри SVG убраны, HP выводится с обводкой поверх части тела; травмы рисуются геометрией части. Цвета и токены не менялись.

## 6. Текущее состояние после разбора форка

В ветке `feat/companion-spec-stage-1`:

- Ручная прокачка переименована в **«Становление»**; в этом режиме можно изучить
  профессиональный навык прямо в листе, а до сохранения видно прошлое значение,
  прибавку и итог.
- Внедрена тема A: тёмный лак, терракота, бронза, тёмный Material; плита перерисована
  (лицо, волосы, кисти, стопы, складки), градиент здоровья непрерывный.
- Травмы: `Отсечена` (культя), `Увечье` (−1 максимум HP, помятые края), `Пронзена`
  (стрела), `Кровотечение`, `Шрам`; физические травмы несовместимы, кровотечение и шрам
  сочетаются. Травма создаёт связанный эффект и окно описания.
- Эффекты добавляются и правятся во всплывающем окне; модификаторы показываются
  человекочитаемо. Эффект `Увечье` содержит модификатор «Максимальное здоровье
  локации» −1; его можно изменить в том же окне.
- Тёмная тема доведена до UI-kit: `color-scheme: dark`, явные цвета `option`,
  отдельные токены hover (`--ui-hover` / `--ui-hover-ink`); тексты и фон hover
  больше не сливаются, списки и нативные селекты читаемы.
- Стрела `Пронзена` уменьшена и вставляется в часть тела; для всех семи локаций
  проверено, что конец стрелы внутри контура, а начало — снаружи. Кровотечение
  рисует яркий порез и капли, шрам — короткую линию по размеру части; при отсечении
  кровотечение и шрам переносятся на культю.
- Адаптивность: характеристики и поля Frame/Рост/Вес больше не перекрываются
  (flex-wrap, характеристики до 58 px), локации получили фиксированные колонки
  d20/HP/AP и переходят в одну колонку до 900 px, числовые плитки ограничены
  111 px, карточки эффектов — 485 px; карточка и вкладки — не шире 1114 px.
  Проверено на 2560/1920/1440/1360/1280/1024/900/720/390/320 px.
- Кубики: сервис `services/dice.ts` разбирает выражения `2d6+1d8−3`, `d100`,
  ограничивает 50 кубиками/100 гранями, использует криптографический d100 через
  rejection sampling; ручной режим принимает физические значения. В окне навыка
  выбирается ступень сложности, показываются цель/Critical/Fumble, доступны
  виртуальный и физический d100, результат и объяснение; история проверок хранится
  только в памяти компонента. В шапке есть общий лоток «Кубики» с выражениями и
  сеансовой историей бросков. Анимация и undo/redo изменений персонажа ещё не
  сделаны.
- В «Становлении» производные атрибуты показывают `↑ +N` / `↓ −N`, если изменились
  из-за характеристик.
- Из листа добавляются оружие (с фильтром по боевым стилям), броня, предметы и
  заклинания Folk Magic / Sorcery / Theism.
- Быстрый урон удалён.
- `npm run build` проходит, `npm run test:compat` — **110/110**.
- Следующие шаги: завершить P2 (анимация кубиков, undo/redo изменений персонажа,
  ссылки на правила), затем P1 (степени ран, восстановление, управление эффектами),
  P3 (снаряжение/профиль в «Становлении»), P4 («Опыт») и P5 (печать/мобильная панель).
  Полный план — в `design/COMPETITOR-FORK-ANALYSIS.md`.


## 7. Очередь на обсуждение · 19.11.2026

Этот список отделяет задачи из UX-аудита от прежних предложений по развитию.
Порядок ещё предстоит согласовать.

- **Исправления для игры.** «Отмена» закрывает черновик новой травмы. Ручной
  штраф брони отмечен в листе и сбрасывается кнопкой «Вернуть авторасчёт».
  Мобильная панель навыков управляет фокусом и закрывается по Escape.
- **Короткие сценарии.** Вернуться из проверки Атлетики в Movement с результатом
  прыжка. Подтверждать добавление брони в запас. Показывать старую предысторию
  как доступный для чтения и копирования текст. Решить, доступна ли запись об
  известном духе персонажу без Анимизма.
- **Развитие.** Уточнить объём первого релиза «Опыта» рядом со «Становлением»
  (ER, тренировки, изучение), затем согласовать модель нескольких культов
  и учений с миграцией сохранений.
- **Работа за столом.** Обсудить отдельный режим игры, управление эффектами
  и их длительностью, печать Companion, мобильную навигацию и термины.
